# 基本設計

## 1. システム構成

AWS東京リージョン（ap-northeast-1）に金融系システムを想定したWebアプリケーション基盤を構築する。

メイン環境として `financial-ai-vpc` を使用し、VPC間通信の検証用として `peering-lab-vpc` を構築する。

```text
                         Internet
                            │
                            ▼
                    Internet Gateway
                            │
                            ▼
              ┌─────────────────────────┐
              │    financial-ai-vpc     │
              │       10.0.0.0/16       │
              │                         │
              │  ┌───────────────────┐  │
              │  │   Public Subnet   │  │
              │  │    10.0.1.0/24    │  │
              │  │                   │  │
              │  │ financial-web-    │  │
              │  │ server (EC2)      │  │
              │  └───────────────────┘  │
              │                         │
              │  ┌───────────────────┐  │
              │  │  Private Subnet   │  │
              │  │   10.0.11.0/24    │  │
              │  │                   │  │
              │  │ Future Backend    │  │
              │  └───────────────────┘  │
              │                         │
              └────────────┬────────────┘
                           │
                      VPC Peering
                           │
              ┌────────────▼────────────┐
              │    peering-lab-vpc      │
              │      10.10.0.0/16       │
              │                         │
              │  ┌───────────────────┐  │
              │  │   Public Subnet   │  │
              │  │    10.10.1.0/24   │  │
              │  │                   │  │
              │  │ peering-lab-ec2   │  │
              │  └───────────────────┘  │
              │                         │
              └─────────────────────────┘
```

---

## 2. VPC

### financial-ai-vpc

CIDR:

```text
10.0.0.0/16
```

金融系Webアプリケーション基盤を配置するメインVPCとして使用する。

### peering-lab-vpc

CIDR:

```text
10.10.0.0/16
```

VPC PeeringによるVPC間通信を検証するためのVPCとして使用する。

VPC PeeringではCIDRが重複しているVPC同士を接続できないため、`financial-ai-vpc` と重複しないCIDRを設定する。

---

## 3. Subnet

### financial-ai-vpc Public Subnet

CIDR:

```text
10.0.1.0/24
```

用途:

- インターネット接続が必要なリソースの検証
- 現在の `financial-web-server` EC2を配置
- 将来的にPublic ALBを配置

### financial-ai-vpc Private Subnet

CIDR:

```text
10.0.11.0/24
```

用途:

- インターネットへ直接公開しないEC2
- RDS PostgreSQL
- バックエンドアプリケーション

最終構成ではWebアプリケーション用EC2をPrivate Subnetへ配置し、Public SubnetのALB経由でアクセスする構成を想定する。

### peering-lab-vpc Public Subnet

CIDR:

```text
10.10.1.0/24
```

用途:

- VPC Peeringの疎通確認
- `peering-lab-ec2` の配置
- Systems Manager Session Managerを利用した管理

---

## 4. Internet Gateway

Internet GatewayをVPCへ接続し、Public Subnetからインターネットへ通信するために使用する。

Public Route Tableに以下のデフォルトルートを設定する。

```text
0.0.0.0/0 → Internet Gateway
```

Private Subnetについては、インターネットから直接アクセスできない構成とする。

---

## 5. Route Table

### financial-ai-vpc Public Route Table

```text
10.0.0.0/16  → local
0.0.0.0/0    → Internet Gateway
10.10.0.0/16 → VPC Peering
```

`10.10.0.0/16` 宛ての通信をVPC Peeringへルーティングする。

### financial-ai-vpc Private Route Table

```text
10.0.0.0/16 → local
```

現時点ではVPC内部通信のみを想定する。

### peering-lab-vpc Route Table

```text
10.10.0.0/16 → local
10.0.0.0/16  → VPC Peering
0.0.0.0/0    → Internet Gateway
```

`10.0.0.0/16` 宛ての通信をVPC Peeringへルーティングする。

---

## 6. VPC Peering

以下の2つのVPCをVPC Peeringで接続する。

```text
financial-ai-vpc
10.0.0.0/16
        │
        │ VPC Peering
        │
peering-lab-vpc
10.10.0.0/16
```

VPC間通信にはPrivate IPを使用する。

検証対象:

```text
ICMP (ping)
HTTP (TCP 80)
```

VPC Peering接続後、双方のRoute Tableへ相手VPCのCIDRを追加する。

## 7. EC2

### financial-web-server

用途:

```text
金融系Webアプリケーション用Webサーバー
```

構成:

```text
OS      : Amazon Linux 2023
Web     : Apache HTTP Server
Subnet  : 10.0.1.0/24
Private : 10.0.1.124
管理    : AWS Systems Manager Session Manager
```

Apache HTTP Serverを稼働させ、VPC Peering経由でHTTP通信できることを確認する。

### peering-lab-ec2

用途:

```text
VPC Peering疎通確認用EC2
```

`peering-lab-vpc` の `10.10.1.0/24` Subnetへ配置する。

`financial-web-server` とのPrivate IP通信を検証する。

---

## 8. Security Group

Security Groupでは必要な通信のみ許可する。

### financial-web-server

主な許可通信:

```text
ICMP    ← 10.10.0.0/16
TCP 80  ← VPC Peering経由の検証通信
```

EC2管理用のSSH（TCP 22）はインターネットへ公開しない。

### peering-lab-ec2

VPC Peeringの疎通確認に必要な通信を許可する。

```text
ICMP ← 10.0.0.0/16
```

---

## 9. EC2管理方式

EC2への管理アクセスにはAWS Systems Manager Session Managerを使用する。

IAMロール:

```text
financial-ec2-ssm-role
```

AWS管理ポリシー:

```text
AmazonSSMManagedInstanceCore
```

SSHポートをインターネットへ公開せず、IAMベースでEC2を管理する。

---

## 10. VPC間通信

VPC Peeringを経由して以下の通信を検証する。

### ICMP

```text
financial-web-server
        │
        │ ping
        ▼
peering-lab-ec2
```

および逆方向の通信を確認する。

結果:

```text
4 packets transmitted
4 received
0% packet loss
```

双方向のPrivate IP通信に成功。

### HTTP

`peering-lab-ec2` から `financial-web-server` へHTTPアクセスする。

```bash
curl http://10.0.1.124
```

結果:

```html
<h1>Hello World!</h1><p>My AWS Financial AI Platform</p>
```

VPC Peeringを経由したHTTP（TCP 80）通信に成功。

## 12. 設計方針

- EC2への管理はSystems Manager Session Managerを使用する
- SSH（TCP 22）はインターネットへ公開しない
- RDSはPrivate Subnetへ配置する
- Security Groupでは必要な通信のみ許可する
- VPC間通信にはPrivate IPを使用する
- VPCのCIDRは将来的な接続を考慮して重複を避ける
- インターネット公開が必要な通信はALBを入口とする
- 検証環境ではコストを抑え、必要なリソースのみ起動する
