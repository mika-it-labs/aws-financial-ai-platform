# 1. システム概要

## 1.1 目的

金融系システムを想定し、AWS上でWebサーバー基盤を設計・構築する。

本プロジェクトでは、以下の技術を習得する。

- AWSネットワークの設計・構築
- EC2によるWebサーバー構築
- IAMロールによる権限管理
- Systems Manager Session Managerによるサーバー管理
- Security Groupによる通信制御
- VPC PeeringによるVPC間通信
- Private IPを利用したシステム間通信
- HTTPによるアプリケーション疎通確認
- 障害発生時の原因調査と復旧
- Terraformによるインフラ構成のコード化

本環境は学習用であり、実際の金融取引や顧客情報の処理には使用しない。

# 3. VPC Peering詳細設計

## 3.1 接続対象

```text
financial-ai-vpc
10.0.0.0/16
        │
        │ VPC Peering
        │
peering-lab-vpc
10.10.0.0/16
```

VPC Peeringを利用して、異なるVPCに配置されたEC2間をPrivate IPで通信させる。

---

## 3.2 通信要件

| 通信 | 送信元 | 宛先 | 用途 |
|---|---|---|---|
| ICMP | financial-ai-vpc | peering-lab-vpc | 疎通確認 |
| ICMP | peering-lab-vpc | financial-ai-vpc | 疎通確認 |
| HTTP TCP 80 | peering-lab-vpc | financial-web-server | Web通信確認 |

インターネット経由ではなく、VPC Peeringを経由したPrivate IP通信を使用する。

---

## 3.3 疎通確認

結果：

```text

```

**結果：成功**

### HTTP

`peering-lab-ec2` から `financial-web-server` へHTTP通信を実施した。

```bash
curl http://10.0.1.124
```

結果：

```html
<h1>Hello World!</h1><p>My AWS Financial AI Platform</p>
```

**結果：成功**

# 8. 障害・トラブルシューティング設計

## 8.1 VPC CIDR重複

既存環境との接続検討時に、双方のVPCで `10.0.0.0/16` が使用されていることを確認した。

CIDRが重複するため直接VPC Peeringを構成せず、検証用として以下のVPCを新規作成した。

```text
peering-lab-vpc
10.10.0.0/16
```

### 学習結果

VPC間接続を考慮する場合、ネットワーク設計段階でCIDR重複を避ける必要がある。

---

## 8.2 Session Manager接続障害

`peering-lab-ec2` 構築時、Session Managerで接続できない事象が発生した。

確認項目：

```text
IAM Role
   ↓
AmazonSSMManagedInstanceCore
   ↓
IAM Trust Relationship
   ↓
SSM Agent
   ↓
Route Table / Internet接続
```

IAMロール、権限、ネットワーク経路等を確認し、最終的にSession Managerから接続できる状態まで復旧した。

---

## 8.3 ICMP成功・HTTP失敗

VPC Peering経由のping成功後、HTTP通信が一時的に失敗した。

```text
ICMP
  ↓
成功

HTTP TCP 80
  ↓
接続失敗
```

Apacheの状態およびSecurity GroupのTCP 80設定を確認した後、再度HTTP通信を実施した。

```bash
curl http://10.0.1.124
```

結果：

```html
<h1>Hello World!</h1><p>My AWS Financial AI Platform</p>
```

最終的にHTTP通信に成功した。

### 学習結果

ICMPが成功していても、アプリケーション通信が正常とは限らない。

障害発生時は以下の順番を基本として切り分ける。

```text
Network / VPC Peering
        ↓
Route Table
        ↓
Security Group
        ↓
OS
        ↓
Service
        ↓
Application
```

# 11. コスト管理設計

本環境は個人学習用のため、必要以上のAWS料金を発生させない。

基本方針：

1. 検証に必要な時間のみEC2を稼働する。
2. 不要になった検証用リソースは停止または削除する。
3. EC2停止後もEBS等の料金発生有無を確認する。
4. NAT Gatewayは現段階では作成しない。
5. AWS Billingで利用状況を確認する。
6. 有料サービス追加前に料金への影響を確認する。
7. 検証終了後は `peering-lab` など不要な検証用リソースを削除する。
