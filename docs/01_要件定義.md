# 要件定義

## 1. システム概要

金融系企業の社内業務システムを想定し、AWS上にWebアプリケーション基盤を構築する。

AWSのネットワーク、コンピューティング、データベース、ストレージ、監視、バックアップ、AI/RAGなどを組み合わせ、金融系システムで求められるセキュリティ・可用性・運用性を考慮した構成を検証する。

また、複数VPC間のシステム連携を想定し、VPC Peeringを利用したPrivate IPによるVPC間通信についても検証する。

---

## 2. 利用者

- 社内ユーザー
- システム管理者
- 運用担当者

---

## 3. 必要機能

### 3.1 Webアクセス

WebアプリケーションをAWS上で稼働させ、利用者からHTTP/HTTPSでアクセスできる構成とする。

検証環境ではAmazon EC2上にApache HTTP Serverを構築し、Webサーバーとしての動作を確認する。

### 3.2 データベース

Amazon RDS for PostgreSQLを利用し、Webアプリケーションからデータを保存・参照できる構成とする。

データベースはインターネットから直接アクセスできないPrivate Subnetへ配置する。

### 3.3 ファイル保存

Amazon S3を利用し、システムで使用するファイルやバックアップデータなどを保存できる構成とする。

### 3.4 システム監視

Datadogを利用し、EC2をはじめとするAWSリソースの状態を監視する。

主な監視対象として以下を想定する。

- CPU使用率
- メモリ使用率
- ディスク使用率
- EC2の稼働状態
- Webサーバーの稼働状態
- アプリケーションログ

### 3.5 障害通知

監視対象で異常を検知した場合、運用担当者へ通知できる仕組みを構築する。

### 3.6 バックアップ

Amazon RDSの自動バックアップ機能を利用し、障害発生時にデータを復旧できる構成とする。

### 3.7 AIによる社内文書検索

AI/RAGを利用し、社内文書を自然言語で検索・参照できる仕組みを構築する。

### 3.8 VPC間通信

異なるVPCに配置されたシステム間で、インターネットを経由せずPrivate IPを利用して通信できる構成とする。

VPC Peeringを使用し、Route TableおよびSecurity Groupを適切に設定する。

検証では以下の通信を確認する。

- ICMP（ping）によるVPC間疎通
- HTTP（TCP 80）によるWebサーバーへのアクセス
- 双方向のPrivate IP通信

## 4. 非機能要件

### 4.1 可用性

本番環境を想定した最終構成では複数AZを利用し、単一AZ障害によるシステム停止のリスクを低減する。

検証環境ではコストを考慮し、必要に応じて単一AZ構成で検証を実施する。

### 4.2 セキュリティ

以下のセキュリティ要件を設定する。

- データベースをインターネットへ直接公開しない
- Security Groupによって必要な通信のみ許可する
- EC2管理用のSSH（TCP 22）をインターネットへ公開しない
- EC2への管理アクセスにはAWS Systems Manager Session Managerを利用する
- IAMロールを利用してAWSリソースへのアクセス権限を管理する
- 必要最小限のアクセス権限を設定する
